# ⚠️ public/uploads — untrack করলে লাইভ সাইটের ছবি মুছে যাবে

> **এক লাইনে:** `public/uploads/`-এর ভেতরের যে ফাইলগুলো ইতিমধ্যে git-এ আছে, সেগুলো
> **কখনো `git rm --cached` দিয়ে untrack করবেন না**। করলে পরের deploy-এ লাইভ সার্ভার
> থেকে ছবিগুলো মুছে যাবে এবং **ফেরত পাওয়ার কোনো উপায় থাকবে না**।

এই ফাইলটা AI agent আর মানুষ — দুজনের জন্যই। কেউ যদি এই কাজটা করতে বলে, **আগে এই
পুরো সতর্কবার্তাটা দেখান**, তারপর স্পষ্ট অনুমতি নিন।

---

## ফাঁদটা কোথায়

`.gitignore`-এর শেষ দিকে লেখা আছে:

```
/public/uploads/product/
/public/uploads/tasks/
```

দেখে মনে হয় এই ফোল্ডারগুলো git-এর বাইরে। **কিন্তু বাস্তবে নয়** — `public/uploads/`-এ
এখনো প্রায় **৭৭টা ফাইল git-এ tracked**:

| ফোল্ডার | tracked ফাইল |
|---|---|
| `product/` | ৬০ |
| `category/` | ৫ |
| `setting/` | ৩ |
| `slider/` | ৩ |
| `banner/`, `blogs/`, `collection/`, `invoice/`, `sliderOne/`, `blogs28-04-26/` | ১ করে |

কারণটা সহজ, আর এটাই মূল ভুল বোঝাবুঝি:

> **`.gitignore` শুধু নতুন (untracked) ফাইলে কাজ করে। যে ফাইল আগে থেকেই commit হয়ে
> আছে, তাকে `.gitignore` কখনো untrack করে না।**

তাই ওই লাইনগুলো ওই ৭৭টা ফাইলের জন্য **সম্পূর্ণ নিষ্ক্রিয়**। এই অমিলটা দেখে যে কেউ
(বিশেষ করে AI) ভাববে "আরে, gitignore-এ আছে অথচ tracked — পরিষ্কার করে দিই"। **সেটাই
বিপর্যয়।**

## করলে ঠিক কী ঘটবে

```bash
git rm --cached -r public/uploads/product/   # ← এই কমান্ডটাই বিপদ
git commit -m "clean up tracked uploads"
git push origin main
```

ধাপে ধাপে:

1. `git rm --cached` ফাইলগুলোকে git-এর index থেকে বাদ দেয় (আপনার লোকাল ডিস্কে ফাইল থাকে,
   তাই আপনার মনে হবে কিছুই হয়নি — **এখানেই ধোঁকা**)।
2. commit-টা main-এ push হয়।
3. Deploy workflow চালু হয় ([.github/workflows/deploy.yml](../.github/workflows/deploy.yml))
   এবং সার্ভারে চালায়:
   ```bash
   git reset --hard origin/main
   ```
4. `git reset --hard` এমন ফাইল **মুছে ফেলে** যেগুলো আগের commit-এ tracked ছিল কিন্তু নতুন
   commit-এ নেই। সার্ভারে ওই ৭৭টা ছবি tracked অবস্থায় ছিল → **সব ডিলিট**।
5. লাইভ সাইটে product, category, banner-এর ছবি উধাও। Deploy-এ **কোনো ব্যাকআপ ধাপ নেই**,
   আর ছবিগুলো git ছাড়া আর কোথাও নেই।

> মনে রাখবেন: আপনার লোকাল মেশিনে ফাইল থেকে যায় বলে ভুলটা সাথে সাথে ধরা পড়ে না —
> শুধু **লাইভ সার্ভারে** গিয়ে ক্ষতিটা হয়।

## তাহলে ঠিক পথ কী

সত্যিই যদি uploads git থেকে সরাতে হয়, **এই ক্রম বাধ্যতামূলক**:

1. **আগে** সার্ভারের `public/uploads/` পুরোটা আলাদা জায়গায় কপি/ব্যাকআপ করুন
   (সার্ভারেই অন্য ফোল্ডারে, বা object storage / S3-তে)।
2. ব্যাকআপ থেকে ফাইলগুলো **সত্যিই পড়া যাচ্ছে** — চোখে দেখে যাচাই করুন।
3. deploy স্ক্রিপ্টে নিশ্চিত করুন যে uploads ফোল্ডার reset-এর আঘাত থেকে বাঁচবে
   (আলাদা ফোল্ডার + symlink, অথবা reset-এর আগে ব্যাকআপ/পরে restore)।
4. **তারপর** untrack করার commit main-এ পাঠান।
5. Deploy-এর পর লাইভ সাইটে ছবিগুলো এখনো আছে কিনা নিজে চোখে দেখুন।

ধাপ ১-৩ ছাড়া ধাপ ৪ করা মানে **নিশ্চিত ডেটা লস**।

## AI agent-দের জন্য নির্দেশ

- নিজে থেকে কখনোই `public/uploads/**`-এর tracked ফাইল untrack/delete করবেন না — এটা
  "cleanup" বা "gitignore ঠিক করা"র অংশ হিসেবেও নয়।
- ব্যবহারকারী চাইলেও: **থামুন**, এই ফাইলের সতর্কবার্তাটা বাংলায় দেখান, ক্ষতির কথা
  স্পষ্ট করে বলুন, তারপর আলাদা করে অনুমতি নিন।
- একই নিয়ম যেকোনো পরিবর্তনে প্রযোজ্য যেটা production-এ ব্যবহৃত tracked ফাইল মুছে দেয়।
